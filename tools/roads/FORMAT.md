# Контейнер доріг UARDS001

Один файл, у якому дороги для авто з OpenStreetMap порізано на плитки 0,1° × 0,1°.
Створює `build_roads.py`, читає `verify_roads.py` (еталон для Java-читача).
Усі багатобайтові числа — **big-endian** (як `java.io.DataInputStream`).
Координати — цілі **мікроградуси** (1e-6°, ≈ 0,11 м).

## Заголовок (32 байти)

| зсув | тип | значення |
|---|---|---|
| 0 | 8 байт | магія `UARDS001` |
| 8 | int32 | версія формату = 1 |
| 12 | int32 | розмір плитки, мкград = 100000 (0,1°) |
| 16 | int32 | широта нижнього краю сітки, мкград (кратна розміру плитки) |
| 20 | int32 | довгота лівого краю сітки, мкград |
| 24 | int32 | nLat — рядків плиток |
| 28 | int32 | nLon — стовпців плиток |

## Індекс (nLat × nLon × 12 байт, одразу за заголовком)

Для плитки (ti, tj), ti — від нижнього краю на північ, tj — від лівого на схід:
запис № `ti * nLon + tj`: `int64 offset` (від початку файлу), `int32 length`.
`length = 0` — плитка порожня.

## Плитка

`length` байт за `offset` — **zlib** (deflate з заголовком zlib; Java `Inflater`).
Після розпакування:

```
varint nSegments
nSegments × Segment
```

`varint` — беззнаковий LEB128 (як у protobuf: 7 біт на байт, старший біт —
«є продовження»). `svarint` — varint від zigzag-кодованого знакового числа:
`zigzag(v) = (v << 1) ^ (v >> 63)`, назад: `(u >>> 1) ^ -(u & 1)`.

```
Segment:
  u8      class        0 motorway, 1 trunk, 2 primary, 3 secondary, 4 tertiary,
                       5 unclassified, 6 residential, 7 living_street, 8 service,
                       9 motorway_link, 10 trunk_link, 11 primary_link,
                       12 secondary_link, 13 tertiary_link, 14 track
  u8      oneway       0 ні, 1 у напрямку точок, 2 проти напрямку точок
  varint  wayId        OSM way id (для довідки/дедуплікації)
  varint  nodeA        OSM node id першої точки — вузол перехрестя або кінець дороги
  varint  nodeB        OSM node id останньої точки
  varint  nPts         точок ≥ 2
  nPts × (svarint dLat, svarint dLon)
          перша точка — відносно ПІВДЕННО-ЗАХІДНОГО кута плитки
          (lat0 + ti·tile, lon0 + tj·tile); кожна наступна — відносно попередньої
```

## Властивості

- **Відрізок = ділянка дороги між двома перехрестями** (вузол, що входить у ≥ 2
  дороги). Зв'язність графа — через спільні `nodeA`/`nodeB`: у два відрізки з
  однаковим node id можна проїхати один з одного. Це готова основа для
  переходів у прив'язці до дороги (HMM).
- Відрізок записано **в кожну плитку, якої торкається його обмежувальна рамка**.
  Довгий відрізок траси є в кількох плитках. Читаючи 3×3 плитки навколо себе,
  дублікати прибирати за ключем `(wayId, nodeA, nodeB)`.
- Геометрія спрощена Дугласом–Пекером (типово 2 м); кінці відрізків — не спрощені.
- Вузли без координат (обрізаний витяг) розривають дорогу на цьому місці.
- Не беруться: `highway=area=yes`, footway/path/cycleway/steps/pedestrian/bridleway
  тощо; `track` — за бажанням (`--no-track`).

## Пошук найближчої дороги (як у verify_roads.py)

1. `ti = floor(lat·1e6 / tile) − lat0 / tile`, аналогічно `tj`; перевірити межі сітки.
2. Прочитати плитки (ti±1, tj±1), розпакувати, прибрати дублікати.
3. Для кожного відрізка — відстань від точки до ламаної у локальних метрах
   (`x = lon·111319,5·cos(lat)`, `y = lat·111319,5`), проєкція на ланку з
   обмеженням `t ∈ [0, 1]`.

У пам'яті застосунку доцільно тримати розпаковані 3×3 плитки навколо поточної
позиції і перечитувати при переході в іншу плитку.
